# Prior art, borrowable detection logic, and latency ideas

**Date:** 2026-09-27
**Status:** Research notes. Nothing here is a decision; items that change behavior go through the design specs first.
**Method:** web search plus reading the READMEs and source of the projects named below (shallow clones). Dates are the GitHub `pushed_at` values seen on the scan date. Claims taken only from a README, not verified in source, are marked *(README)*.

inumaki is agent-first. The problem it addresses is AI agents sweeping up personal data from tool results without the user noticing, and sending it out of the country. Detection is a means to that end. This note answers three questions:

1. Does an open-source project already cover inumaki's agent-layer combination?
2. Which mature detection logic can inumaki borrow instead of re-inventing, under its Apache-2.0 license?
3. Which architecture and latency techniques from adjacent projects apply to the measured 5 KB latency miss?

## 1. Prior art at the agent layer

### Verdict

No open-source project found combines all of:

- a transparent MCP-layer proxy that sanitizes tool results **and** rehydrates tool arguments for arbitrary upstream servers,
- tokens that persist per dataset across sessions in an encrypted vault,
- an independent verifier that blocks before transmission,
- DACH German names, addresses, and identifiers,
- a CPU-only Rust latency budget.

Several projects cover parts of this. The README should name the closest ones and state the differences.

The two most-cited overlaps, Kiji and CloakPipe, both fail the central agent case when read at source level: neither sanitizes `tool_result` content blocks on the Anthropic request path, which is where agents carry the personal data they read. Section 4 has the details.

- [Dark-Moon](https://github.com/ASCIT31/Dark-Moon) (GPL-3.0): a pentest agent whose "Privacy Gateway" tokenizes infrastructure data and rehydrates it at tool execution. It uses the same pattern but is not reusable.

### MCP security gateways

None of these do reversible PII tokenization:

- Lasso mcp-gateway: Presidio masking, irreversible.
- Docker MCP Gateway: secrets and interceptors, no PII handling.
- Trail of Bits mcp-context-protector: server pinning and prompt-injection quarantine.
- Invariant Gateway (now Snyk): guardrails through a hosted service.
- ressl/mcp-firewall (AGPL): detection and policy, no reversal.

### Status of the mature detection projects

- **Presidio** has moved from Microsoft to community governance at [data-privacy-stack/presidio](https://github.com/data-privacy-stack/presidio). It is MIT-licensed and active.
- **LLM Guard** was archived on 2026-07-09. Its last release was v0.3.16 (May 2025), after Palo Alto Networks acquired Protect AI.

### EU and DACH research

No agent-layer open-source release was found. Relevant papers:

- Fraunhofer, resource-efficient text anonymization, [COLING 2025 industry track](https://aclanthology.org/2025.coling-industry.20.pdf).
- "Zero-Shot Anonymization of Customer Communications in German", [SciTePress 2026](https://www.scitepress.org/Papers/2026/144903/144903.pdf).
- DFKI Medinym (clinical text) and the KI-AIM Cinnamon platform (structured and medical data).

### Ideas worth taking

- **Per-tool, per-argument disclosure policy** (mcp-pvp): a field contract states which tool may receive a real value and which only the token. This fits the M4 field contracts.
- **Hook-plus-gateway layering for Claude Code** (claude-cloakpipe) as an alternative or complement to the MCP shim.

## 2. Borrowable detection logic

### Gap confirmed in the code

The sanitizer does not propagate a detected name to its other mentions in the same document. `stoplist::name_parts` (`crates/inumaki-core/src/stoplist.rs`) is used only by the verifier's leak check (`crates/inumaki-core/src/verify/second_pass.rs`) and by eval's residue measurement. The verifier therefore knows that "Sarah" belongs to "Sarah Leitner" and blocks the document, while the sanitizer could have tokenized the mention. In dataset mode the known-entity detector emits only full names and surnames, which is the first-name block recorded in `docs/threat-model.md`.

### Recommendations, ranked by expected effect on the leak rate

1. **Spread names within a document, and take names from email addresses.** This is inumaki's own logic, patterned on talon.
   - After detection, collect each PERSON span's name parts with `name_parts`, including ae/oe/ue/ss transliteration. Tokenize every other occurrence as the same entity.
   - Split email local parts on `.`, `_` and `-`. Promote a part to PERSON when it is in a first-name list or appears elsewhere in the text.
   - This applies the verifier's own leak rule in the sanitizer, so it should lower both the accepted-leak rate and verifier blocks.
2. **Greeting and sign-off anchors plus a first-name gazetteer.**
   - Anchors: `Hallo X`, `Liebe X`, `Servus X`, `Sehr geehrte Frau Mag. X`, and the short line after `LG`, `VG`, `MfG`, `Mit freundlichen Grüßen`, `Beste Grüße`, `Kind regards`.
   - Anchor plus gazetteer hit gives high confidence. Anchor alone gives lower confidence.
   - Add the Presidio context boost for NER spans after these anchors.
   - Keep a stoplist of ambiguous names such as Ernst, Frank, Mai, Rose and Grün.
3. **A differently trained verifier model.** The held-out accepted-leak rate (11.8 %) suggests the sanitizer and verifier share blind spots. Evaluate `gliner_multi_pii-v1` or the ai4privacy model against held-out PERSON recall and CPU latency.
4. **Presidio's German recognizers and DACH checksums**, plus BEV and swisstopo street gazetteers. Business email rarely contains these identifiers, so the effect on the synthetic leak rate is modest.
5. **Generated secret rules** from gitleaks or noseyparker in one `RegexSet` with an Aho-Corasick keyword prefilter, `p_random` for unlabeled tokens, and `scheme://user:pass@` for any URL scheme. A leaked secret is the worst failure, but secrets are rare in business email.

## 3. Architecture and latency

### Where the time goes

The deterministic stage uses a `RegexSet` prefilter and stays under 1 ms. The 5 KB cost (about 800 ms cold through the daemon) comes from two models running back to back on every chunk. The M2 spike measured GLiNER at about 61 ms and the token classifier at 52–74 ms on 121 words. The verifier's `bert-base-multilingual` (12 layers) is heavier than the primary gliner-x-small.

Batching and parallel sessions spread the same work over more cores, roughly 1.5–3× on 4–10 cores. Reaching the 13× needed for 60 ms also requires doing less work: fewer tokens, a smaller verifier, and reused results. On a 4-core mini PC, 60 ms for 5 KB may not be reachable with the current models, and a per-KB target may be more honest.

**Before any change:** run ONNX Runtime's profiler once (`SessionBuilder::with_profiling`) to split time per model and per chunk.

### Tier A: large impact, recall unchanged

- **A1. Share weights and threads across pooled sessions.**
  - Each session currently uses `min(4, available_parallelism)` intra-op threads (`crates/inumaki-models/src/backend.rs`), so two or more pooled sessions oversubscribe a 4-core box.
  - Use `EnvironmentBuilder::with_global_thread_pool`, bounded spinning (see [ORT threading](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)), and shared initializers or prepacked weights. That reduces the ~170 MB cost of each extra slot.
  - Low effort. A prerequisite for M4 plan 4's parallel inference.
- **A2. Batch all chunks into one model call per model.**
  - The `ort` maintainers recommend "one session per thread or batch multiple requests at once" ([ort #402](https://github.com/pykeio/ort/issues/402)).
  - [gline-rs](https://github.com/fbilhaut/gline-rs) builds padded GLiNER batch tensors (`src/model/input/encoded.rs`), and [text-embeddings-inference](https://github.com/huggingface/text-embeddings-inference) batches under a token budget (`core/src/queue.rs`).
  - In inumaki: add `predict_batch` to `NerBackend`, pad `words_mask`, `span_idx`, `span_mask` and `text_lengths` in `gliner.rs`, batch-encode with padding in `token_classifier.rs`, and sort chunks by length in `detector.rs`.
  - The gateway should batch across content slots too, so a structured result with 50 short fields does not pay a model call per field.
  - Expected 1.3–2× on 5 KB of text, much more on results with many fields.
- **A3. Do not sanitize structured tool results twice.**
  - The [MCP tools spec](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) says a tool returning `structuredContent` SHOULD also return the serialized JSON as a text block.
  - When a text block parses to exactly the `structuredContent` value, emit the serialized sanitized structure instead of scanning it again. Deduplicate identical slot strings.
  - Up to 2× on structured results. The text block then follows the field contract's preserve rules; record that in the M4 spec.
- **A4. Cache NER results per chunk by content hash.**
  - Pattern: noseyparker's `BlobIdMap` skip of already-scanned content.
  - Key: model id, label and threshold fingerprint, and a keyed hash of the chunk text. Value: offsets, labels and scores only, in memory, with a per-process key.
  - The verifier's input is cacheable as well, because suffix masking makes it independent of token values.
  - Agent loops re-read the same data (pagination, quoted threads, retries), so only changed chunks re-run.
  - `chunk::cut_point` already prefers sentence and line breaks, but it searches a window measured from the previous cut, so an early edit can shift every later boundary. Content-defined cut points, anchored on paragraph breaks as in FastCDC, restore alignment after an edit.
  - Recall is unchanged as long as inference is deterministic.

### Tier B: large impact, recall must be re-measured with `eval`

- **B1. Send fewer tokens to NER.** Replace spans that policy will tokenize anyway (URLs, emails, IBANs, secrets, base64 and hex blobs) with short placeholders before NER, and skip segments with no letters. Deterministic detectors still run on the full text. Risk: changed context around neighboring names.
- **B2. A smaller verifier.** `Davlan/distilbert-base-multilingual-cased-ner-hrl` has the same labels and tokenizer family with 6 layers instead of 12, and an ONNX export exists (`Xenova/…`). Roughly 2× on the verifier half. It is the backstop, so gate it on verifier false negatives and held-out PERSON recall.
- **B3. Fuse the graph, then quantize, per platform.** Run ONNX Runtime's transformer optimizer, then dynamic int8, at model build time only. ORT warns that int8 can be slower on old CPUs, and x86 without VNNI can saturate. Benchmark per target CPU and pin the variant in `models/manifest.toml`.
- **B4. Pipeline GLiNER and the verifier.** The verifier can check chunk *i* while GLiNER processes chunk *i+1*. Running the token classifier on the original text as a second detector would raise recall, but it would weaken "the verifier independently checks the outgoing bytes" for the model part. That needs a spec amendment first.

### Tier C: small win or not recommended

- **Label-prompt and word-id caching** in `gliner.rs`: a few milliseconds, trivial.
- **Hyperscan or vectorscan:** needs cmake and boost for a stage already under 1 ms. If secret rules grow into the hundreds, use gitleaks-style Aho-Corasick keyword gating instead.
- **GLiNER bi-encoder:** mostly English models, and inumaki uses few labels. Skip.
- **A cheap classifier gating whether NER runs:** weakens recall. Only provably safe gates are acceptable: cache hit, no letters, or text already fully replaced.
- **Sequence packing:** needs variable-length attention kernels. Use length-sorted batches instead.
- **LLM Guard and Presidio** both process chunks sequentially, so there is no latency technique to borrow from them.
- **NeMo Guardrails `stream_first`** sends tokens before checking, the opposite of inumaki's rule.

### Streaming rehydration (proxy)

- vLLM holds back `max(len(stop)) - 1` characters until a partial stop string resolves (`vllm/v1/engine/detokenizer.py`). inumaki can do the same for tokens:
  - hold back from the last unclosed `<` up to the maximum token length and flush everything else at once;
  - run strict rehydration at stream end;
  - rehydrate tool-argument deltas after JSON unescaping.
- [TensorZero](https://github.com/tensorzero/tensorzero) (`crates/reqwest-sse-stream`) is a Rust reference for SSE parsing with under 1 ms p99 gateway overhead. Per-delta work must stay proportional to the delta.

### Suggested order

1. Profiling split.
2. A1, then A2 and A3.
3. A4.
4. B2 and B1, each behind eval gates.
5. B3 per platform.
6. B4, after a spec amendment.

## 4. CloakPipe and Kiji at source level

Both projects were read at source level: CloakPipe at commit `f09ebc9` (2026-08-30) and Kiji at `c916161` (2026-09-14). Paths are relative to each repository. Kiji's model files are Git LFS pointers in a shallow clone, so its model was not run.

### Corrections to the README-level picture

- **Kiji does not mask tool results.**
  - `src/backend/providers/anthropic.go:128-148` masks only `text` blocks and string content, and skips `tool_result`, `tool_use`, `system`, images and documents.
  - The Responses path masks `instructions` and item `content` only, so `function_call_output`, `function_call.arguments` and `reasoning` leave in clear.
  - The shipped model is DeBERTa-v3-base with a CRF layer, not DistilBERT.
  - Storage is plaintext SQLite. Only API keys are encrypted, through Electron `safeStorage`.
- **CloakPipe's streaming is buffered.**
  - `crates/cloakpipe-proxy/src/streaming.rs` reads the whole upstream body with `response.text().await` before emitting anything.
  - `input_json_delta` is never rehydrated.
  - The vault's `save()` is called only from tests, so the proxy's "persistent" vault is memory-only in practice.
- **CloakPipe does have a transparent stdio MCP interceptor** (`crates/cloakpipe-mcp/src/proxy.rs`), but in the opposite direction to inumaki. It masks `tools/call` arguments going to the tool and restores tokens in results coming back to the agent, which protects the tool from the agent rather than the cloud model from tool results.

### What they do better, and what inumaki should take

Ranked by value to the agent-first goal.

1. **Streaming codec details** (Kiji, `src/backend/proxy/streaming.go:139-258`, `codec_anthropic.go`, `codec_openai.go`). Fold into engine spec §8.3 now; build with the proxy.
   - JSON-escape restored originals inside `input_json_delta` and function-argument deltas. inumaki's tokens need no escaping, but real values can contain `"`, `\` or control characters.
   - Rehydrate the full-text repeats in `*.done`, `output_item.done` and `response.completed` events. Codex renders its final message from these.
   - Keep one carry buffer per content block or channel index, never split a UTF-8 character, and flush at stream end.
   - Detect SSE by content when `Content-Type` is missing, and pin replies to HTTP/1.1 for Codex.
   - Refuse `Upgrade`/WebSocket requests with 501, which fails closed.
   - Port the codec test cases as fixtures (Apache-2.0, keep the notice): no chained substitution, multibyte characters intact, tool arguments remain valid JSON, carry tail flushed at EOF.
2. **Tripwire on model-authored text** (idea from CloakPipe `crates/cloakpipe-proxy/src/handlers.rs:157-190`, inverted).
   - Scan tool-call arguments before rehydration, and model responses, for known originals in clear. Use the dataset's known-entity Aho-Corasick detector plus the deterministic detectors.
   - A hit means the model already holds a real identifier, through an unrouted chat, an unwrapped tool, or the user typing it.
   - Record kinds and counts only, and notify the user.
   - This is the most direct signal for "the agent took data without the user noticing". Small effort; fits the M4 gateway's rehydrate path.
3. **Session-scoped name propagation with an ambiguity rule** (CloakPipe `crates/cloakpipe-core/src/session.rs:216-256,300-303`).
   - A bare first name or surname gets an in-scope PERSON's token only if exactly one in-scope PERSON has that part. Otherwise it gets a fresh PERSON token, so it is still tokenized.
   - This extends §2 recommendation 1 across the messages of one session, and answers the open first-name question in `docs/threat-model.md` more safely than dataset-wide propagation.
   - Re-measure the block rate and conflation with eval.
4. **A user-awareness journal and per-entity forget** (Kiji's activity and mappings views, `src/backend/server/handler.go:1194-1318`).
   - Store what actually left the machine: the sanitized payload per request, encrypted under the vault key with a short TTL, rehydrated locally only on demand.
   - Add entity listing and single-entity erase in `inumaki-vault`. Today only a whole dataset can be deleted.
   - This goes beyond the integration spec's counts-only activity view (§11.3), so it needs a spec amendment. It must never go through `tracing`.
5. **Activity records that cannot hold personal data by construction** (CloakPipe `crates/cloakpipe-ledger/src/record.rs`, `tests/no_pii_invariant.rs`).
   - Typed per-hop records: front door, upstream id, direction, kinds and counts, verdict, check ids, opaque request id, and a keyed hash of the sanitized bytes.
   - No free-text fields, and a property test of the invariant. An optional `prev_hash` chain gives cheap tamper evidence.
   - Skip the signatures, Merkle batching and timestamp anchoring; they serve third-party compliance, not user awareness.
6. **Alias groups in dictionaries** (CloakPipe `crates/cloakpipe-core/src/resolver.rs:22-31,60-72`). Listed variants ("Hans-Peter Gruber", "HP Gruber", "Hansi") share one token, so users can cover nicknames no model will catch. Rehydration returns the canonical form.
7. **Kiji's NER model as a candidate third backend** (`DataikuNLP/kiji-pii-model-onnx`).
   - Apache-2.0, trained on DE/AT/CH text among others, with separate `FIRSTNAME` and `SURNAME` labels.
   - It needs CRF/Viterbi decoding in `crates/inumaki-models/src/token_classifier.rs`, roughly 60 lines ported from `onnx_model_detector.go:350-406`.
   - Measure it on the tuning and held-out corpora, including bare sign-offs, before adopting it. Kiji publishes no accuracy numbers.
   - Kiji's data pipeline (LLM-generated text, Label Studio review, a first-name-only labelling rule) is a template for fine-tuning inumaki's own classifier.
8. **An eval track for structured tool results** (idea from CloakPipe `crates/cloakleak/corpus/tool_json`). Nested JSON fields and numeric IDs with gold spans from inumaki's own generator, with recall and leak rate reported per track. CloakLeak's corpus itself is small, India-centric, and scored circularly.
9. **Codex with ChatGPT login.** Kiji configures `model_providers.kiji` with `requires_openai_auth=true` and `supports_websockets=false`. A short spike should test whether Codex forwards its session to a localhost base URL. If it does, the integration spec's "hooks only" for that mode could become fully proxied.
10. **Packaging before the setup app.** A Homebrew cask and a `.deb` with a systemd user unit; Kiji's `DynamicUser=yes` is a cheap step toward Protected mode's separate service user.

### What neither project should teach

- **Failing open.**
  - Kiji returns the original text when the detector is missing or errors (`src/backend/pii/masking_service.go:60-79`), and forwards the original body when re-serialization fails.
  - CloakPipe forwards raw text on MCP detection errors (`crates/cloakpipe-mcp/src/proxy.rs:146`), disables NER when its sidecar is unreachable, silently generates an ephemeral key when none is configured, and opens its SQLite vault with a wrong key.
- **Originals in logs.** Kiji's `LogVerbose` is on by default (`src/backend/config/config.go:328`) and prints original request bodies. Its ONNX detector prints every entity's text with `fmt.Printf`.
- **Rehydration oracles.**
  - CloakPipe uses `CorsLayer::permissive()` with no authentication, its Docker config binds `0.0.0.0`, and its tokens are sequential (`PERSON_1`). Any web page or LAN host can ask for `PERSON_1`…`PERSON_50` and read the rehydrated values back.
  - Kiji's admin API listens on all interfaces, reflects any `Origin` with credentials, and exposes `/api/mappings` and `/api/logs` without authentication by default.
  - Any inumaki HTTP front door must validate `Origin` and never enable permissive CORS.
- **Substring rehydration of realistic dummies** (Kiji). Short dummies such as `Li` or `7` rewrite unrelated text and code, and two originals can share a dummy.
- **Fuzzy name merging** (CloakPipe, Jaro-Winkler ≥ 0.90). It merges Christina/Christian Huber, Stefan/Stefanie and Müller/Möller. In an agent loop, tool arguments would be rehydrated to the wrong person.
- **Byte offsets across case mapping** (CloakPipe `crates/cloakpipe-core/src/session.rs:680-700`). Lowercasing changes byte lengths for `ẞ`, so German text panics or yields wrong spans.
- **Over-powered interception CA** (Kiji). 10-year validity, no name constraints, installed system-wide.
- **Misclassification reports sent to a third-party service** (Kiji to Sentry). A report of a missed identifier contains that identifier.
- **Plaintext storage with dead retention code** (Kiji `database.go`), and one global mapping table linking all contexts.

### Where inumaki is already ahead

- Covers `tool_result` and tool arguments at the MCP layer.
- Has an independent verifier before send.
- Uses opaque delimited tokens that cannot collide with ordinary text.
- Keeps an encrypted per-dataset vault with rotation epochs.
- Fails closed on model, detector and storage errors.
- A canary test guarantees originals never reach logs.
- Validates DACH identifiers with checksums.
- Has measured, held-out evaluation.
- Its control API is a mode-0600 Unix socket.
