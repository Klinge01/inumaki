## Known limits at sign-off

- **One mirror worker (G2).** With the default `[mirror] workers = 1`, one first read parked on a macOS privacy prompt stalls every folder, including the check's own mirror folder, whose path then fails closed after its 30 s wait. Answering the prompt ends it.
- **Blocking calls on an unanswered prompt (G3, verified 2026-10-11).** `lstat`, `realpath`, and registering an FSEvents watch on a protected folder return at once while the privacy prompt is open; only reading inside the folder (listing, opening a file) waits for the answer (`docs/research/2026-09-29-m5-tcc-spike.md`, G3 follow-up). Daemon start and adding or rescanning such a folder do not hang on them; the first read is covered by the G2 item above. Not tested: event delivery for a folder whose grant is pending or denied.
- **Ad hoc signing.** Every upgrade has a new code hash: folder grants are lost and macOS prompts again, the Keychain may ask again, and a downloaded `.dmg` needs right-click → Open (`docs/packaging.md`). Binaries are replaced by rename, never in place.
- **Codex with a ChatGPT login is unverified.** `CODEX_CHATGPT_VERIFIED = false`; the user-gated run of plan M8-3 Task 5 (2026-10-10) failed with `privacy_block`. The cause is fixed and development runs passed on 2026-10-28 (see above), but the gated run is not repeated. The per-harness traffic recording of Task 4 is done (M8 spec §4 amendment of 2026-10-10).
- **Harness traffic through the proxy was refused under `support-email` and `strict`; fixed for Codex and Claude Code on 2026-10-28.** Measured before: Codex 0.159.2 (2026-10-10), and Claude Code 2.1.296 (2026-10-11) with 8 `PERSON` hits with check `Policy` and 1 `CONTRACT_ID` with check `Regex`. GLiNER's escalation band flagged the harness's own static text (model instructions, skills, permission fragments, the system prompt) as PERSON, and `on_uncertain = "block"` refused the request. `[proxy] harness_static_ner = "skip"` (the default) now runs the leading prompt without the name models; see threat model (ee) to (hh) and `docs/harness/codex.md`. Other harnesses (Hermes Agent, OpenClaw) are not measured.
- **Cold scan of a long conversation.** The first request of a long conversation after a daemon restart or a session expiry re-scans the whole history, because the incremental cache is in memory; it can take seconds. The Responses and Codex-items wire carries about 2.5 to 2.9 times as many strings as Messages for the same text and costs more, per turn and on the cold scan.
- **Latency figures.** The published proxy figures are from 2026-10-05 (`offline`: cold first turn about 3.4 s, p50 52.9 ms and p95 70.4 ms added per turn) and are experimental; the runs of 2026-10-09 were on a loaded machine and are not published. A quiet-machine series is pending.
- **`support-email` refuses long histories.** On the long synthetic proxy history every turn is refused (`451`): the model's escalation band under `on_uncertain = "block"` and a disagreement between the sanitizer's and the verifier's name recognizers, which needs engine and profile work.
